# SwiftProof v0.2.0

This release measures which changed lines a recorded test run actually executed,
and reports added Go lines that never ran as review signals.

## Included

- Optional `coverage` command in trusted policy. Its argument vector must contain
  the token `{coverage_out}` exactly once; SwiftProof expands that token to the
  in-container profile path and never appends a coverage flag of its own, so the
  executed argument vector is the one you reviewed.
- Each added line of a changed non-test Go file is reported in exactly one of four
  states: executed, not executed, not inside any instrumented block, or not
  measured. Lines that were not executed become `uncovered_change` signals,
  medium severity, or low when the coverage run itself did not pass.
- A new `coverage` object in `confidence-report.json` and a new
  **Changed-line Execution** section in `CONFIDENCE_REPORT.md`, with the recorded
  profile retained as a SHA-256 hashed artifact.
- The coverage profile leaves the sandbox as a length-declared framed payload on
  the container's standard output, separately bounded and separate from the
  captured log. No writable host path, no additional mount, no volume and no
  container that outlives the run were added.

## Upgrading

Existing `.swiftproof.json` files do not acquire the new key automatically, and
nothing changes for a repository that does not add it: no container runs, no
signal is emitted and the exit code is unchanged. `swiftproof init --language go`
seeds the key for new configurations.

A policy containing a `coverage` key is **rejected by SwiftProof v0.1.0**, which
exits 3 on an unknown command name. If a pinned older binary reviews your pull
requests, publish and re-pin this release before committing the key to your base
branch. See [CI integration](../CI.md).

## Installation

Download the archive for your operating system and architecture, verify its entry
in `SHA256SUMS`, extract it, and put `swiftproof` (`swiftproof.exe` on Windows) on
your PATH. Run `swiftproof version` to verify installation.

Git is required. Docker with Linux containers and a preloaded toolchain image is
required only for executing repository checks, including the coverage run. Go is
not required to run the downloaded CLI.

## Current limits

Coverage measurement is Go only. Absent, truncated, unparsable or unmapped profile
data is always reported as not measured, never as not executed, so a file whose
package produced no instrumented block yields no signal at all. Without
`-coverpkg`, a line exercised only through another package's tests is reported as
not executed. There is no base-side comparison, no coverage regression detection,
no threshold gate and no percentage.

Executed means the line ran at least once during the recorded run. It is not
evidence that the line is tested, asserted, correct or safe. This remains a 0.x
release: signals and passing checks are not a correctness guarantee and never
automatically approve or merge a pull request. Archives are not signed or
notarized. See README.md and SECURITY.md for setup and execution boundaries.
